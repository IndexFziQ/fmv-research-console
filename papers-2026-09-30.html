Scaling Long-Form Story Generation via Narrative State Tracking

架构 9分相关
Zhennan Wan, Jianfei Chen PDF ↗
LLM 在创意写作上表现强劲，但把故事扩展到「长篇小说」级仍困难——叙事一致性随长度增加越来越难维持。现有故事生成方法大多止步于约 1 万词，长篇小说能力鲜少被探索。作者提出 NstAgent，一个免训练的智能体框架，让 LLM 追踪结构化的「叙事状态」，包括角色、过去事件与未来要求。作者扩展既有基准以跨长度比较叙事一致性，并结合写作质量基准，系统评测 10K 到 100K 词的故事。结果表明 NstAgent 在故事变长时叙事一致性与写作质量更好，且两者都未随长度显著下降——为「把故事生成扩展到长篇」提供了有效路径。代码开源。
核心问题：AI 写故事一写长就崩：角色、伏笔、因果链越写越乱，如何让长篇叙事保持一致？
解决方案：用「叙事状态追踪」框架，显式维护角色/已发生事件/未来要求三类结构化状态，让模型写作时始终有据可依，从 10K 到 100K 词都不崩。
对你有什么用：互动影游最怕「剧情一长就穿帮」。NstAgent 的「叙事状态追踪」思路可直接映射到你的多分支剧情引擎——把「角色状态 + 已发生事件 + 未兑现伏笔」做成显式状态，正是影游长线剧情一致性的底层解法。

架构 8分相关
Alessandro Emmanuel Pecora, Stefano Calzolari, Francesco Strada, Andrea Bottino PDF ↗
创造可信的虚拟人（VH）需要感知、推理、动作三者在语言中介下连贯整合，核心难点是把它组合成一个扎根于交互式 3D 环境的控制闭环。作者提出 A.D.A.M.O.，一个语言驱动的视觉-符号框架，借助预训练 VLM 的工具调用能力，在单一控制闭环中统一感知、推理与动作。A.D.A.M.O. 维护一个「视觉+符号」双重世界模型，融合第一人称视觉输入与同步的符号状态，支持从自然语言提示出发的扎根任务导向行为。作者还引入一个按「认知难度」分类的受控任务套件，把空间任务拆成程序复杂度与语言复杂度两轴。实验显示语义标注强烈影响任务完成与失败模式——它降低了感知歧义、把失败转移到下游执行，而推理错误相对罕见。
核心问题：虚拟人如何在 3D 环境中把「看、想、做」连贯起来，用自然语言驱动可信的交互行为？
解决方案：视觉+符号双世界模型 + VLM 工具调用，把感知/推理/动作统一进一个控制闭环，用认知难度分类的任务套件做诊断性评测。
对你有什么用：影游做「可交互虚拟角色」时，视觉-符号双重世界模型是让角色「看得见场景、又记得状态」的关键。A.D.A.M.O. 的闭环设计可直接参考，帮你把 NPC 从「只会对话」升级成「感知场景+执行动作」的具身角色。

EP-Mem: Elastic Privacy Memory for Social Relationship-Aware LLM Agents

架构 8分相关
Fengzhou Sun, Yuan Zhang, Xintong Yu, Jinyao Yan PDF ↗
LLM 智能体在「人-智能体-人」沟通中扮演代表角色时面临严重隐私风险。为防止泄密，智能体必须理解用户的社会关系、遵守依赖上下文的社会信息披露边界。现有智能体记忆隐私研究只关注即时交互，长期的关系性披露问题仍属空白。作者提出 EP-Mem（弹性隐私记忆架构），把隐私重构为「用户拥有的、跨社会角色的边界控制」。EP-Mem 引入：(1) 由用户可配置隐私策略驱动的 token 级记忆，对人员与事件分层，结合领域级默认流通规则与事实级白名单/黑名单例外；(2) 可插拔的 sidecar 隐私引擎，在摘要/细节/边界三个粒度上对齐披露控制与记忆，贯穿生成、存储、检索全程。作者构建 EP-Bench（首个跨会话关联事件的长期多方基准）。实验显示 EP-Mem 隐私分类准确率 94.0%、披露许可判断从 22% 提升到 68%、隐私泄漏降低 75.6%。
核心问题：AI 角色在「替用户传话/代持身份」时，如何按社会关系边界决定「哪些该说、哪些不该说」？
解决方案：把隐私做成「用户拥有的跨角色边界控制」：可配置分层策略 + 事实级白/黑名单 + 三粒度（摘要/细节/边界）sidecar 隐私引擎。
对你有什么用：影游里角色若持有玩家或他人的「秘密」，就面临同样的披露边界问题。EP-Mem 的「关系分层 + 白/黑名单 + 三粒度披露控制」是现成的设计范式，可帮角色「该守口如瓶时绝不剧透」——这是沉浸感与信任感的隐形支柱。

HiThink Turn: An Intent-Aware Turn-Taking Control Module for Full-Duplex Dialogue

硬数据 8分相关
Feiyang Chen, Wenhan Yang, Bohan Wang, Xinjian Gao, Rongjunchen Zhang, Jun Wang, Xinhui Hu PDF ↗
全双工对话需要「及时但选择性」的打断处理，仅靠话尾预测做不到：完整话语可能无需回应，而未说完的请求反而该被适时打断。作者提出 HiThink Turn，一个意图感知的流式话轮状态预测器，把「回应意图」与「语义完整性」分离，并让决策依赖于系统播放状态。关键贡献是「最小意图充分前缀监督」——通过 LLM 判断与语音对齐构建，同时在块边界截断的音频上训练以提升对部分语音的鲁棒性。这些组件支持 240ms 音频块的流式推理，实现低延迟、准确的全身工话轮控制。实验显示 HiThink Turn 在 Easy Turn 宏准确率、Full-Duplex-Bench 平均交互率得分（0.933）等指标上领先，意图前缀触发把打断成功率从 89% 提升到 98%、平均停止延迟降低 60.9%。
核心问题：全双工对话里，AI 什么时候该接话、什么时候该打断，光看「话说没说完」远远不够，怎么办？
解决方案：把「回应意图」和「语义完整性」拆成两个独立信号，用最小意图充分前缀 + 流式 240ms 音频块做话轮状态预测，兼顾低延迟与高准确。
对你有什么用：影游若做「实时语音对话」角色，打断/接话时机直接决定自然度。HiThink Turn 的「意图与完整性分离」思路，能帮你的角色「该抢话时抢话、该倾听时闭嘴」，避免尬聊式的话轮错位。

On Evaluating and Improving Conversational Agents in Production

作者提出一个评测与改进生产环境大规模多智能体购物助手的框架，并报告实践教训。此类系统的离线评测面临三个障碍：(i) 已记录的对话无法对修改后的系统重放，因为不同的响应会改变后续每一轮；(ii) 未修改的系统本身每次运行也变化——LLM 组件随机，商品、价格、个性化信号都在变；(iii) 聚合质量分数混合了不同行为，只能看出质量变了、却看不出是哪个行为导致的。框架逐一应对：对报告的行为，评测工具（Evaluation Harness）生成定向断言与固定的客户场景队列，通过扎根的用户仿真在本地实例中复现该行为；用模拟器按记录的消息与上下文生成新的用户话轮而非重放日志；未修改系统的重复运行构成存储基线；改进编排器（Improvement Orchestrator）把断言结果转成假设、逐个隔离实现并对比基线。报告了生产实践调查。
核心问题：生产环境里的对话 agent 无法离线重放评测，如何定位「哪个行为变差了」并验证改进？
解决方案：定向断言 + 扎根用户仿真复现行为 + 存储基线 + 隔离式假设改进，用配对分位数 bootstrap 区分真实改进与随机波动。

持久记忆让语言模型智能体在长期协作中携带信息，却留下生命周期问题：当共享状态已变，一个「归来」的智能体还能依据什么行动？一段记忆可以检索正确、与当前任务相关、且忠实于来源，却仍「不可采纳」——行程单里保存的酒店可能已被团队换掉。作者把这个问题形式化为「时序记忆准入」，提出 TRACE，一个免训练层，把「再入场」当作资格决策而非存储/检索操作：对照缺席期间的更新调和离开时的检查点，解析显式与隐式失效，仅当返回视图覆盖归来角色的未了义务时才释放有界 Return View。在 Memora、STALE Type II 等基准上，TRACE 是唯一在两个维度都高的方法——有效信息可用性 92.6-98.3%、无效信息拒绝 98.4-99.5%。
核心问题：多智能体协作中，离开再回来的 agent 如何知道「哪些旧记忆已失效、哪些仍有效」？

对你有什么用：影游里角色「下线再上线」或「剧情跨度后重逢」，最怕记着已经作废的旧事。TRACE 的「时序记忆准入」思路，能帮角色在时间跳转/剧情推进后精准区分「仍成立的记忆」与「已失效的记忆」，避免穿帮。

基于 LLM 的多智能体系统在复杂问题求解上展现出潜力，随着方法多样化，系统评测愈发困难。现有基准大多只看最终结果，无法看清「协作增益如何产生、保持或丢失」。作者提出 MASTraceBench，通过多智能体系统中的「提案轨迹」诊断协作增益。在六个合作与竞争任务上，MASTraceBench 追踪并分级提案轨迹，提供多层指标套件（任务得分、协作增益、提案轨迹指标、token 成本）。作者系统比较代表性 MAS 方法，发现一个反复出现的模式：最终答案很少超越最强的初始提案——交互往往把较弱的初始提案拉向它，而强提案很少被进一步改进、甚至可能退化。为降低该风险，作者提出 CLEARS，用跨智能体的「主张级评估」取代整体提案交换来引导可靠综合，在六个任务中的五个上取得最高协作增益。

LLM 越来越多地被用作交互智能体，但当公共通信不可靠时，其协调鲁棒性仍不清楚。作者在迭代 N 玩家「猎鹿博弈」中研究这一问题，由同质 LLM 群体在受控的程序化动作反转下进行——这同时改变公开转录与用于执行的动作。在覆盖群体规模、协调阈值、腐败水平与七个 LLM 的实验网格上，观察到三个主要模式：第一，随腐败增加，诚实智能体的「翻转前」猎鹿选择下降，但公开成功率的骤降主要是机械性的（N=5,M=3 下翻转前成功保持 78%、公开成功降至 12%）；第二，诚实选择与决策时可见的公开历史相关，尤其在高腐败下；第三，三个阈值式公开报告基准与 LLM 智能体的动作匹配率相近，说明 LLM 决策与这些基准存在显著描述性一致。结论：评估多智能体鲁棒性时必须分离「原始选择、公开动作、执行结果」。EMNLP 2026 Workshop。

解决方案：在猎鹿博弈中引入受控动作反转，量化「原始选择 vs 公开动作 vs 执行结果」三层，揭示腐败通信如何可预测地破坏互利协作。

Share-Borne AI Virus: Memory-Hopping Attacks Across LLM Agents

架构 7分相关
Sidharth Pulipaka, Ansh Sharma, Stanislau Hlebik, Leonidas Raghav, Vyas Raina, Ivaxi Sheth, Mario Fritz PDF ↗
LLM 越来越多地被部署为有状态助手，跨交互保留信息，并用工具读取、修改、创建持久化产物。当这些产物在用户间共享时，它们构成了本应独立的助手之间的间接通信渠道。作者研究这一渠道促成自我传播攻击的失效模式，提出「产物介导传播」：通过产物（如报告）引入的对抗性内容被存入助手的持久记忆、复现于随后创建的产物中、并被稍后读取它的另一助手获取。在时序人-智能体宇宙中评估该过程，测量攻击能否在连续交接中存活、能跳多少跳、扩散多广。发现攻击可跨多个独立助手传播并在长交互序列中持续；在更大仿真环境中，即使 GPT-5.6 Luna 也表现出显著扩散，60-80% 的智能体被感染、传播链长达 8 跳。

解决方案：形式化「产物介导传播」攻击，在时序多智能体宇宙中量化攻击的存活、跳数与扩散范围，揭示持久产物是持久的对抗状态载体。
对你有什么用：若影游允许角色「读写共享记忆/文件」，这篇是安全警钟——恶意或污染内容会像病毒一样在角色间自我传播。它提醒你在设计角色间信息共享机制时，要内置「内容可信度校验」，否则一条被污染的记忆会毒化整条剧情线。
